# 0067 / 0071 — shared pipeline and selection tables

Selection now starts from the vehicle's pursuits instead of the sparse manual-factor table.
Both pages share a searchable, sortable table, with New and Sourcing enabled by default on
Selection and an All view on Pipeline. Scores reuse the existing fit assessment or the
vehicle-scoped provisional strategy score; strategy action priority remains a separate
measure. Missing evidence stays unscored. Wrong-vehicle strategies cannot supply a score.

Organisation groups retain each person's status and evidence, and direct organisation
records show affiliated people. Compact labelled filters share one line with search;
status buttons compress in one row. Every data column sorts, capacity sorts numerically,
and only the first 50 groups render initially while search covers all loaded pursuits.

Selected pursuits support audited bulk status changes, touchpoints, team context, requests
for research/connections/strategy, and feedback. Bulk records are transactional and
idempotent, preserve next steps and refuse stale statuses. Touchpoint reconciliation may
create draft approval tickets; nothing sends or accepts consent. Workflow requests stay
reviewable on LP timelines and are explicitly not scheduled or running.

`docs/specs/nl-sort.md` specifies future natural-language sorting, costs, privacy and the
Agent seam. No LLM sorting runtime was implemented.
