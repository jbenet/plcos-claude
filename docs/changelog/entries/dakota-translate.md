Developer → Enrichment now has an **Import Dakota** button. It runs only in the live server's process, reads complete local replicas, and returns counts. A first import replays complete incremental batches in order; unchanged records and repeat imports preserve database state. New tables retain only the public schema's needed fields, modification dates and replica provenance.

Accounts become source-owned organisations and contacts become people, with tier-C employment ties. Website domains, LinkedIn URLs, CRDs and CIKs can corroborate identity; names alone remain possible matches. Merges retain the identity module's reversible redirects and correction constraints.

LP pages show **Claims from Dakota**, including a separately labelled capacity estimate and grouped contacts. A title-based likely first contact is stored on the account. Thesis and ticket rules add New account pursuits with explicit rule reasons, skip pursued or restricted identities, and retain a configurable cap of 150 per vehicle (a GUESS). Capacity provides a sourced fallback without changing commitments or consent.

Dakota claims stay in their own database projection. Research exports omit Dakota-associated identities and affiliations; previews omit the raw Dakota folder. Once Dakota is present on the real profile, file feedback and screenshot capture are refused before the capture drawer opens, because those paths persist outside the database. Existing connection feedback is also refused on that profile. Real feedback no longer captures images or persists browser drafts, so an already-open drawer cannot race a later import. This restriction can be replaced by database-only feedback intake later.
