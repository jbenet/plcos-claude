# Routes 0084–0088 — source, identity and path correctness

Team members, including evidenced PL staff without app logins, now start their own routes. PL prefixes are shortened and duplicates removed; PL remains a fallback only when no particular team relationship is recorded. A source-roster fingerprint invalidates cached searches when staff membership changes.

Paths cannot repeat a canonical or possible person identity. Same-name and active possible-match records are checked conservatively, without merging source identities. Matching records share one map node, while the comparison list retains their evidence. For example, two unmerged records for the invented “Avery Moss” cannot become an introduction from Avery to Avery.

Every read checks do-not-contact instructions on sources and intermediaries, including canonical aliases and the selected vehicle. Removed paths appear in a separate disclosure with their reason. Organization hops receive a size discount and are removed at the configured limit. Defaults are explicitly GUESS values: 8 distinct graph members, 500 publicly recorded employees, and a discount scale of 50. The low graph limit reflects sparse coverage; it is not an assertion of actual organization headcount. Public counts require provenance, and missing counts stay unknown.

The map assigns layers across the whole route union, including cyclic unions, so no arrow stays within a layer. Extra hops can widen the graph; available width expands the drawing without scaling fonts. The graph and keyboard-accessible comparison use the same selected routes.

It shortened 328,934 source prefixes and removed 250,241 duplicates, 9,431 repeated-person paths, 43,696 redundant PL fallbacks, 215 restricted-person paths, and 9,254 organization-hub paths. Prefix changes overlap removals; removal reasons are counted sequentially. Across stored visible graphs, 1,081 same-layer relationships became zero; 915 repeated possible-person node appearances were identified for grouping. Search coverage remains bounded by the existing hop and per-source candidate limits.
