## Query evidence and implementation

Full `EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)` plans are private under `data/real/perf3-explain-*.json`; predicates can contain real identifiers. The committed numbers below contain no records.

| Query experiment | Execution milliseconds |
|---|---:|
| Original relationship roles, restricted to 100 entities | 59,547 |
| Same sample, coinvestor indexes only | 16,201 |
| Set-based roles, first 100 of the full universe | 875 |
| Exact relationship group totals | 398 |
| Bounded pipeline affiliation projection, final plan | 138 |

The original role query scanned the edge table once per entity. Membership sets now resolve facts once, then page in SQL; each group has exact counts and next/previous links. Detail panels request only their own identity and first 100 ties (six in the inspector). Affiliations select bounded IDs through indexed foreign keys before projecting canonical names. `LATERAL` keeps small neighborhood reads from becoming full ordered-index scans; counts remain exact. Network coverage and tier counts aggregate in SQL without loading the complete adjacency graph. Visualization and research previews disclose their caps and preserve unknown states outside the inspected slice.

Every async page loader shares an in-flight promise for the same request identity; completed/failed work is removed. No completed pages are cached. Foreground queued jobs expire at 20 seconds and check their age again immediately before dispatch. Feedback writes its issue file before any database or user lookup; database metadata is best-effort with a 250 ms cancellation scope. These changes require a server restart: an old PGlite wrapper survives development hot reload.

An already executing PGlite query remains uninterruptible. The new guarantees are bounded reads, retry coalescing, and dropping stale queued work; they cannot preempt arbitrary future CPU-heavy SQL already running on the JavaScript thread.
